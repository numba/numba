
Version 0.68.1 (Release Date)
=============================


Performance Improvements and Changes
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``np.sum`` performance regression from ``ArrayIterator``
--------------------------------------------------------

``np.sum`` performance was regressed when ``ArrayIterator`` was adopted. The
innermost loop now uses a static stride constant, which restores vectorization,
and ``order='K'`` iteration over Fortran-layout arrays proceeds in reverse so
the innermost loop does less work.

(`PR-#10850 <https://github.com/numba/numba/pull/10850>`__)

Remove the per-element integer division from advanced indexing
--------------------------------------------------------------

Advanced (fancy) array indexing is now implemented more efficiently, reversing
a 2x performance regression for large arrays introduced in Numba v0.66.0.

(`PR-#10852 <https://github.com/numba/numba/pull/10852>`__)


Bug Fixes
~~~~~~~~~

Fix the accumulator dtypes of reductions to match NumPy
-------------------------------------------------------

The accumulator dtypes of ``np.sum``, ``np.prod``, ``np.cumsum``,
``np.cumprod``, ``np.nansum`` and ``np.nanprod`` now match NumPy: booleans
and integers narrower than NumPy's default integer accumulate into that
integer (``intp``/``uintp``, or ``int32``/``uint32`` on 64-bit Windows with
NumPy < 2.0). In particular ``np.nansum`` and
``np.nanprod`` no longer convert unsigned integer inputs to signed ``intp``.

(`PR-#10866 <https://github.com/numba/numba/pull/10866>`__)

Fix caching of functions imported from a zip archive on Windows
---------------------------------------------------------------

Importing a module that defines a ``cache=True`` function from a zip archive
no longer raises ``KeyError`` on Windows. The path of the module inside the
archive is now built with ``/`` separators, as zip member names require.

(`PR-#10896 <https://github.com/numba/numba/pull/10896>`__)
